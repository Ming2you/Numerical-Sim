# 2026-07-15 offset 가격의 진짜 메커니즘 — 오귀속 2차 정정

## 결론 먼저
**offset 가격의 TTT 이득은 offset 레버와 무관하다.** 이득은 리더가 다른 예산(N_P/N_UF)을
고르는 데서 나온다. offset은 평면에서 안 움직인다(155_w 60스텝 내내 0).

## 증거 1 — 155_w: offset이 양팔 다 0인데 −142
| 155_w | offset max | wTTT |
|---|---|---|
| 동결(joint, 가격OFF) | **0** | 1,796.5 |
| 가격ON + relin K4 | **0** | **1,654.9** (PFO 1,776 대비 −121) |

offset=ref=0이면 가격 항 `g_off × circ_delta(offset−ref)` = **정확히 0** 기여.
trust가 후보를 ±15로 잘라도 양쪽 다 0을 고름 → **팔로워 문제는 사실상 동일**.
그런데 −142. → 차이는 팔로워가 아니라 **리더**에서 나온다.

## 증거 3 — 코드 순서가 경로를 확정 (캐시 버그 아님)
`stackelberg_wu_metered.py:460-461`
```python
self._maybe_refresh_signal_prices(state, forecast, previous)   # 가격 먼저
result = super().decide_with_info(...)                          # 그 다음 리더 탐색
```

가격이 팔로워에 실린 뒤 리더가 **그 팔로워를 내부 시뮬레이션**하며 후보 채점 →
후보 점수 변화 → 다른 N_P*/N_UF*. **설계된 경로**다.

### 정확한 메커니즘 서술
리더 탐색 중 **어떤 반사실적 후보 예산에서는** 자유 팔로워가 offset을 움직였을 것이나,
가격+trust(±15s)가 이를 묶는다 → **후보 점수 지형이 바뀜** → 다른 예산이 승리.
승리 예산에서는 양팔 모두 offset=0.
⇒ 이득 = "offset 조정"이 아니라 **"팔로워 offset 자유도 구속 → 리더 예산 재선택"**.

## 재선형화의 위치
- 190_w: 가격ON relinOFF(offset 0) = 4,735.3 / 가격ON relinK4(offset 105) = 4,733.9 → **relin 기여 1.4**.
- 155_w: relin **발화 자체 안 함**(offset 0).
⇒ relin은 TTT에 무관. 메커니즘 실증("뾰족한 레버도 선형가격+재선형화로 도달 가능")으로서의
   가치만 있고, 그것도 190_w 단일 셀.

## 논문에 쓰면 안 되는 문장
- ✗ "재선형화가 −309를 벌었다" (1차 오귀속 — 이미 정정)
- ✗ "offset 가격이 플래툰을 정렬해 이득" (2차 오귀속 — **데이터가 부정**: offset 불변)
- ✗ "joint 조합 탐색이 해롭다" (전제였던 '가격ON=joint 우회'가 코드상 거짓 — joint은
  가격과 무관하게 실행되고 가격·trust는 joint 솔버 **안에서** 적용됨, L3804/L1659-1687)
